# GPT-5.6 · 提示词消化笔记与结论

> 基于官方《Prompting guidance for GPT-5.6》整理的作者笔记，含概括与改编，不收录官方文档的连续译文段落；非官方文档、无厂商背书，API 参数与价格以官方现行页为准。核对日期 2026-07-26。

## 一、消化笔记

### 1. 最核心的认知转换：提示词不是 SOP，而是验收合同

旧习惯是把模型当新员工，恨不得把鼠标怎么点都写进去；GPT-5.6 的官方方向更像是给成熟执行者一份合同：

```
目标是什么
  ↓
什么叫做完
  ↓
不能越过哪些边界
  ↓
可以调动哪些资源
  ↓
拿什么证明确实做完
```

因此，“写得详细”和“控制得好”已经不是同义词。真正高价值的细节集中在**验收、边界、证据和例外**，低价值的细节往往只是重复叮嘱过程。

### 2. 一套可直接执行的「减法审稿」五问

逐段审查 system prompt、skill 或项目规则时，可以问：

1. 这条删掉会让模型犯哪一种可观察的错？
2. 它是否只是另一条规则的同义反复？
3. 它是在规定结果，还是在过度遥控过程？
4. 这是永远不变的硬约束，还是应写成判断条件？
5. 它能否由测试、schema、权限或 hook 这类确定性机制承担？

五问都答不出价值的内容，优先删。这与「只写删了会犯错的内容」的原则完全同向，也解释了为什么项目指令越堆越长后，实际遵循度反而可能下降。

### 3. `ALWAYS/NEVER` 的预算应该很小

绝对措辞不是“加强语气”的装饰，而是在告诉模型：这里不准做情境判断。用多了会产生两个副作用：

- 每条看起来都最高优先，规则间稍有冲突就难以稳定执行；
- 本来应按风险判断的动作，被扭成机械化的“总要问”或“绝不做”。

真正适合绝对规则的，是安全红线、固定 schema、不可逆动作和法律/业务硬边界。其他场景更适合 `if/then` 决策规则。

### 4. 自主性边界应按「请求类型」定义

官方那段 answer/review 与 change/build 的区分非常实用：授权应来自用户动词，而不是模型自己猜。

| 用户意图 | 默认允许做到哪里 |
|---|---|
| 回答 / 解释 / 审查 / 诊断 / 规划 | 读取、分析、报告，不实施修改 |
| 修改 / 构建 / 修复 | 完成范围内本地改动，并做非破坏性验证 |
| 对外写入 / 删除 / 付费 / 扩大范围 | 停下确认 |

这比到处重复“先问我”更稳，也和「偏好交给短指令、确定性红线交给 hook 与权限」的分层呼应：偏好与判断交给短指令，错一次代价很高的确定性红线交给 hook 或权限系统。

### 5. “少调用工具”不是目标，“最少的有效循环”才是

检索和工具调用的优化顺序应该是：

1. 先保证关键结论有证据；
2. 再删掉不改变答案的调用；
3. 最后才比较 token、耗时和成本。

因此，不能只写“尽量少搜索”。更好的写法是点名**什么缺口值得再搜、什么目的不值得再搜**。这实际上给模型建立了“检索预算”。

### 6. PTC 的判断口诀：压数据，不代替判断

PTC 适合把一大堆结构化中间结果压成小结果；凡是涉及审批、引用保真、原生文件、逐步语义判断的流程，直接工具调用通常更合适。

可以记成：

> **代码负责可重复的数据缩减，模型负责会改变路线的语义判断。**

“调用很多次”本身不是使用 PTC 的理由。

### 7. 长任务的理想可见性：少量、结果导向

官方并不鼓励模型直播每个动作。更好的进度更新是：

- 开始前：一句话说第一阶段做什么；
- 阶段切换：一句具体发现 + 下一步；
- 结束时：结果 + 验证证据 + 未解决缺口。

这比“我现在要打开文件……我接下来要搜索……”更省上下文，也更有信息密度。

### 8. 真正值得复用的中文模板

```text
Role
你在当前任务中的职责与上下文。只写会影响判断的背景。

Goal
交付给用户的最终结果。

Success criteria
- 必须完成的事项
- 必须保留的事实、结构或行为
- 可用于证明完成的检查或证据

Constraints
- 安全、权限、业务与证据边界
- 哪些本地动作可直接做
- 哪些外部、破坏性、付费或扩范围动作必须确认

Tools
- 哪些前置检索或验证不能跳过
- 何时并行，何时必须串行
- 空结果或失败时最多尝试哪些回退

Output
先给什么结论，保留哪些信息，格式与语言是什么。

Stop rules
证据何时算够；何时重试、收窄答案、提出最小问题或停止。
```

使用原则：先从最短版本开始。只有真实 trace 显示某种失败，才补一条针对性指令。

### 9. 我自己的迁移检查单

- [ ] 先只换模型，不改 prompt，不改 reasoning effort
- [ ] 用原来的代表性任务跑基线
- [ ] 记录具体失败，不凭感觉说“变差了”
- [ ] 查重复规则、冲突规则、陈旧示例、无关工具
- [ ] 一次只删或改一组
- [ ] 若要补规则，必须能对应一个实测失败
- [ ] 同一批任务重跑
- [ ] 质量通过后，再比较 token、延迟与成本
- [ ] 最难任务才考虑提高 effort；先排查契约是否缺项
- [ ] 最终检查用户可见结果，而不只看中间工具是否成功

## 二、可带走的结论

1. **先删再加**：GPT-5.6 的提示词优化，默认动作是去重、去冲突、去无关工具。
2. **写终点，不遥控脚步**：结果、成功标准、证据和停止条件比“逐步思考”更有用。
3. **绝对命令只留给真铁律**：判断场景写决策规则。
4. **授权集中写一次**：安全本地动作可继续，外部/破坏性/付费/扩范围动作才确认。
5. **检索要有预算**：只为必要事实、指定材料、穷尽覆盖或关键主张追加搜索。
6. **验证是提示词的一部分**：没有实际检查证据，就不能只凭“工具显示成功”宣布完成。
7. **迁移靠对照实验，不靠整套重写**：一次只改变一个变量，才能知道什么真的有效。

# optimizers/ · 优化器文本与实测状态

> **2026-11-15 说明**：下表与文中数字均为 2026-09 作者报告，是当时执行环境上的历史对照，尚未在 Fable 5.2 / Opus 5.5 / GPT-6.1 上重跑；不要把当时的胜负当成这些新模型的成绩。作者判断：模型越能直接理解自然语言指令，这类优化器的边际价值可能越小。优化器正文未改。

三份**纯文本**，不调用任何服务：
- `task-contract-optimizer.zh.md`（两步式）：贴进「项目指令 / system prompt」，把随手写的任务改写成「目标 / 成功标准 / 约束 / 材料 / 输出」的契约，再由你复制到新对话执行。
- `task-contract-optimizer-inline.zh.md`（一步式）：内部改写后直接执行，契约不输出。
- `generic-optimizer.zh.md`：**评测对照组 C**，模拟市面常见的万能框架提示词，不是推荐方案。

**公开的三份文本（两步式、一步式、对照组 C）都不是评测时的原版**：规则条目与评测版逐字一致，但文首标题、自述句（C 还有可见的对照组说明）在评测后按审查意见改过；脚本会把全文送入模型，所以严格说公开文本未经与表中数字对应的同一次评测。原版文本不随库发布。

## 装法
- ChatGPT（Plus/Pro）：新建项目 → 项目指令贴入两步式全文 → 在项目里发任务得到契约 → 复制到项目外新对话、切到 Thinking 后发送。不要放全局自定义指令（每个对话都会变成改写模式）。GPT-6 在作者任务集上为负，未在其他任务上验证。
- Kimi 网页：项目 → 项目指令，同上。
- DeepSeek 官方端：没有持久指令位，每次对话先贴优化器全文，再贴任务。
- Claude Code / Codex：见仓库根目录 `skills/prompt-contract/`，那是给 agent 用的方法版本，不是这两份文本的直接封装。
